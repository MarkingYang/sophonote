## 产品判断

首要差异不在于模型数量，而在于

− 是否提供更多自动化能力。

+ 是否形成可控、可恢复、可验证的工作闭环。

这一判断引用了 [E1] 架构说明 与 [E2] 实际运行记录。

1 个区域待审阅
书写与审阅

让 AI 靠近正文，但不让它越过你。

Markdown 是正文真相源。AI 修改绑定版本、选区与文本锚点，以逐区域 Diff 呈现；冲突时停止，不猜测覆盖。

  • 编辑、预览与分屏围绕连续书写设计
  • 一次 AI operation 对应一个撤销步骤
  • 保存失败保留草稿，不把失败说成成功
项目工作室

让资料、代码、终端、浏览器和 Agent 在同一现场协作。

工作室面向真实本地目录：看文件、编辑代码、审查变更、运行命令并在 Browser 中查看结果。权限模式始终可见。

边界很重要 普通代码文件由 WorkspaceService 管理；SophoNote 笔记仍只经 DocumentService 写入。

03 / 产品原则

先进能力，
必须配得上清晰边界。

SophoNote 不把“自动化更多”当作唯一目标。真正可信的本地 AI 工具，要让用户始终知道数据在哪里、Agent 看到了什么、修改为什么发生。

阅读技术架构 ↗
01

本地真相源

笔记正文是你能直接读、直接导出的 Markdown；SQLite 只承担元数据、索引、运行与审计。

02

作用域透明

页面不是权限。每一轮只读取显式附件、选择范围与已授权工具，发送后冻结，不随导航悄悄扩大。

03

副作用可审

文档修改先展示 Diff；工具默认拒绝；高风险动作逐次确认。Skill 本身从不等于权限。

04

失败诚实

保存、模型、工具或 Runtime 失败都会留在原位置，保留可恢复状态，不用假步骤或成功文案掩盖。

06 / 常见问题

先把关键问题说清楚。

我的数据真的都在本地吗？

笔记正文、索引、会话映射和应用状态保存在你的 Mac。调用外部模型、抓取来源或你授权的 MCP 时，完成任务所需的最小上下文会发送给对应第三方；SophoNote 自身不提供云端账号或正文遥测。详见隐私说明。

需要自己配置模型吗？

需要。你可以配置受支持的云模型供应商，也可以使用 Ollama、vLLM、LM Studio 等本地或私有化 OpenAI-compatible 端点。项目本身免费开源，但第三方模型可能收费。

AI 会直接改掉我的笔记吗？

不会。AI 只能提出绑定版本、选区和文本锚点的修改提案；你接受后才由 DocumentService 落盘。版本或锚点冲突时系统停止，不做就近猜测替换。

现在支持哪些平台？

macOS 是完整体验和宿主验收平台，公开预览优先提供 Apple Silicon DMG。Windows x64 已有 CI 打包流程，但仍待真实 Windows 宿主验收与 Authenticode 签名；移动端和 Web 端不在当前范围。

SophoNote 与 Hermes Desktop 有什么关系？

SophoNote 使用开源 Hermes Agent 作为执行 Runtime，并拥有自己的知识工作产品壳、数据边界、审批与文档服务。它不是 Hermes Desktop 的分叉，也不复制 Bot Mode、HUD、语音、Memory Graph 或消息通道。
