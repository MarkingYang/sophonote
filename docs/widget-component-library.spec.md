## 1. 背景与定位

### 1.1 产品定位（DEC-042）

> **SophoNote = 兼容 Hermes 最好的 macOS 桌面端，把美观做到极致。**

工具组件（首发基于 DEC-041 注册式组件库）可「添加到桌面」，投影为两类系统原生面：
- **WidgetKit 桌面小组件**（macOS 14+）
- **macOS Tahoe（26）新版控制中心第三方控件**（同一控件可由用户 pin 到菜单栏）

桌面投影是组件的**看 / 动投影**，不创建第二份完整页面；不存在脱离主应用的「桌面版 SophoNote」。

### 1.2 目标体验

- 用户在不打开 SophoNote 主窗的情况下，看到桌面就能**感知到今天用了什么 / 做了什么**；
- 用户从桌面 widget 或控制中心**一键直达**主窗对应工具页；
- 桌面对应的视觉必须**像系统一等公民**（Liquid Glass / 系统 tint / SF Symbols / SF Pro 数字），不自绘 chrome。

### 1.3 包含范围与不包含范围

| 包含 | 不包含（明确划界） |
|---|---|
| WidgetKit `systemSmall` / `systemMedium` / `systemLarge` 三档 | iOS 主屏 widget（iPad 后续单独 PRD） |
| macOS Tahoe（26）`accessoryRectangular` / `accessoryCircular` | 桌面壁纸 / 屏保 widget |
| 菜单栏 pin 控件（由 Tahoe 控制中心控件衍生） | 第二份完整页面 / 替代主窗 |
| 三态主题 + 同源多皮肤架构 | 服务端订阅 / 云同步 |
| 今日时间流专题（暗色玻璃 + 24h 流水） | AI 渲染图直接交付（需替换为自有 3D 模型） |

## 2. 设计原则（铁律）

### 2.1 系统级延伸，不替代主窗

桌面组件 / 控制中心模块**只读 + 一键直达**。组件可以呈现状态、摘要、关键操作入口，**所有写操作跳回主窗**完成（速记提交、任务完成、模型切换、文档修改等）。

### 2.2 只读优先，副作用最小

写副作用（写收件箱、改主题、唤起会话）只走既有主应用通道：
- **DocumentService**：所有笔记 / 项目正文写入
- **QuickCapture**：收件箱写入（168h TTL）
- **Appearance Service**：主题切换
- **Hermes Runtime intent**：任务 / 会话发起

**绝不**绕过以上边界，让 widget / 控制中心直接写主库。

### 2.3 作用域透明

每个 widget / 模块必须在 UI 中明确标注：
- **数据源**：从哪个服务读？（Hermes Runtime / 笔记元数据 / 番茄钟会话记录等）
- **边界**：能做什么？不能做什么？
- **写意图去向**：触发后谁负责执行？

绝不允许跨项目静默串话。

### 2.4 对齐 DEC-041 注册式组件库

widget 注册项与主窗工具域画廊**同源注册**（`desktopWidget` 描述符）。研发侧遵守 DSK-01。

### 2.5 同源多皮肤，一套内核

一套 widget 内核，三态主题（Light / Dark / Tinted）外加可扩展的衍生皮肤；
**任何主题切换不引入 widget 重新实现**，仅换 paint。

### 2.6 真实尺寸交付

Widget 严格按 macOS WidgetKit 真实像素尺寸出图：
- Small ≈ 155 × 155（macOS 14+ widget 出图按 1.5× 比例 = 232 × 232）
- Medium ≈ 310 × 155（出图 465 × 232）
- Large ≈ 310 × 232 起（出图 465 × 348）

**绝不**凭感觉画非标尺寸。

### 2.7 美观优先（DSK-08）

| 必须 | 禁止 |
|---|---|
| Liquid Glass 材质（BACKGROUND_BLUR + 半透明 + 内白描边） | 自绘 chrome（不要画「窗口」边框） |
| SF Symbols 图标 | Emoji / Unicode 图标字形（必须 SVG frame） |
| 系统 tint 着色 | 跨平台 Apple Color（非系统 macOS 标准色） |
| Sarasa Gothic SC（中文）+ Inter（数字） | 非系统允许字体 |
| 圆体 monospacedDigit（数字等宽对齐） | 真彩色（饱和的 RGB 大红大绿） |
| 状态语义色（成功绿 / 告警橙）与主应用令牌一致 | 自主创新色板或私有语义色 |

## 3. 平台硬约束（与 PRD §7.12 DSK 对齐）

> 任何违反本节的设计稿 / 实现都要立即退回重做。

| 约束 | 规则 |
|---|---|
| **DSK-01** | 工具整页与画廊按 `desktopWidget` 描述符显示「添加到桌面」；点击打开投影面板，列出桌面 widget / 控制中心控件两个面，各自「启用同步」+ 放置引导 |
| **DSK-02** | **平台硬约束**：widget / 控件**不能程序化放置**。必须用户手动添加（右键桌面 → 添加小组件；控制中心 → 编辑添加；菜单栏自控制中心 pin）。应用内入口仅承诺「数据同步 + 引导」 |
| **DSK-03** | 桌面 widget 首发 systemSmall / systemMedium 两档；本规格扩展到 systemLarge 用于高密度 widget（热力图 / Memory 增长曲线 / 时间流） |
| **DSK-04** | widget 交互 = 4 个 `Button(intent:)`（开始 / 暂停 / 继续 / 放弃）+ `widgetURL(...)` 深链回整页。复杂操作回整页，**widget 不是第二份完整页面** |
| **DSK-05** | 控制中心控件 = Toggle（专注）+ Button（放弃 / 打开整页）。**控件不承载倒计时活秒**，负责「动」不负责「看」；pin 到菜单栏后带状态着色，单击启动 / 暂停 |
| **DSK-06** | 版本策略：widget 交互需 macOS 14+；控件需 macOS 26（Tahoe）+。非 Tahoe 优雅降级为**仅桌面 widget**，投影面板隐藏控件面 |
| **DSK-07** | **状态单一真相源**：所有投影状态来自 SophoNote（任一域的真实状态），任何投影**不独立持有状态机**；完成计数幂等写入，跨窗口 / 跨投影不重复计数 |
| **DSK-08** | 美观 = 全系统原生（见 §2.7） |
| **DSK-09** | 应用退出后投影**不得显示错误倒计时**：widget 到期态显示完成 / 占位，控件回到就绪态；下次启动幂等对账补记过期会话并刷新全部投影 |
| **DSK-10** | 验收（Tahoe 真机）：桌面 widget 活秒与整页一致；widget / 控制中心 / 菜单栏三处启动暂停状态一致；杀进程重跑后过期会话自动补记完成；非 Tahoe 机器仅 widget 面可用且入口面板正确降级 |

## 5. 设计规范（铁律）

### 5.1 尺寸系统（按 macOS WidgetKit 真实像素 ×1.5）

| 尺寸档 | macOS 真实像素 | 设计稿像素 | 显示尺寸 |
|---|---|---|---|
| Small (S) | ~155 × 155 | 232 × 232 (1.5x) | 232 × 232 容器 |
| Medium (M) | ~310 × 155 | 465 × 232 (1.5x) | 465 × 232 容器 |
| Large (L) | ~310 × 232 起 | 465 × 348 (1.5x) | 465 × 348 容器 |
| Extra L | 流光带专用 | 1508 × 240 | 1508 × 240 流光带（横跨整行） |

### 5.2 差异化骨架策略（A 原则 · 防公式化）

**禁止**所有 widget 用同一种视觉公式。**每个 widget 必须使用差异化的视觉骨架**，避免一眼看上去全是「白底 + 标签 + 大数字 + 副标」。

**当前差异化骨架清单**：

| Widget | 差异化骨架 |
|---|---|
| 年度进度条 | 紫 ribbon + 12 月度彩色染色条（Q1 紫 / Q2 绿 / Q3 橙 / Q4 蓝）+ 双标 |
| 倒数日 | 橙 ribbon + 大字「47 天」+ 4 节日横排带（红 / 橙 / 蓝 / 紫节日块，含日期 + 倒数日） |
| 三年前的今天 | 米黄复古纸张 + 棕褐「TIME CAPSULE · 03」ribbon + 双 chip（#卡片笔记方法论 / #flomo·迁移）+ 棕「打开胶囊」CTA |
| Hermes 状态 | **暗色玻璃**（与浅色 widget 形成画风分水岭）+ 绿 ribbon + 大字运行时长 + 5 节点时间线（启动 / 模型 / 任务 / 记忆+ / 待命）+ 3 指标卡（Tokens / 队列 / 记忆） |
| 今日待办 | 紫 ribbon + 完成 chip「3/5」+ 表头 4 列（时间 / 任务 / 时长 / 状态）+ 任务行（绿勾 / 空心圆 / 时长 / 时间戳）+ 划线已完成任务 |
| 习惯热力图 | 16 周 × 7 天 SVG 热力矩阵 + 头标 + 图例 |
| 情绪天气 | 太阳 SVG + 心情文字「晴 · 平静」+ 副标「连续记录 6 天」 |
| 白噪音 | 声波 SVG + 「雨声 · 播放中」+ 副标「今日已听 2.3h」 |
| 知识资产累计 | 紫「本周 +38」+ 大字「1,247」+ 副标「312 语义版本 · 26 项目 · 100% 本地」 |
| Memory 增长曲线 | 折线 + 渐变面积图 + 末点高亮 + 副标「本周 +23 条 / 全部 486 条」 |
| Token 仪表 | 半圆 SVG 表盘（背景弧 + 进度弧 + 指针 + 中心轴）+ 读数「42.3k」+ 副标「今日消耗 · 预算 100k」 |
| 每日盲盒笔记 | 橙色礼物盒图标 SVG + 「第 128 期」+ 引文悬念 + 揭晓提示 |
| 打字统计 | 数字大字「8,421 键」+ 副标「最常用：退格键 · 高于昨日 12%」 |
| **今日时间线** | **暗色玻璃 + 24h 多色分段 SVG（SophoNote 紫段 / 编辑器蓝 / 浏览器黄 / NOW 绿点）+ 大字「6h 24m」+ 3 mini stat**（最长专注 1h 12m / 启动 18 次 / 离休息 12min） |
| **时间流** | **整宽 1508 SVG 流光带（紫→蓝→青→绿→橙→红渐变）+ NOW 白色圆环标点 + 3 数据对比（6h 24m / 38% / −12%）** |

### 5.3 通用骨架约束（B 模板 · 每 widget 必有 4 区）

虽然视觉差异化，但**任何 widget 都要包含 4 个区域**作为设计骨架：

| 区 | 作用 | 实现方式 |
|---|---|---|
| **① 顶部 ribbon** | 主题色 + 大写语义标签（e.g. `TODAY · SOPHONOTE ACTIVE`），1-2 行内 | horizontal flex，icon + text + right chip |
| **② 中央主体** | 主数据 / 主图（数字 / 折线 / 列表 / 矩阵 / SVG），占 widget 50%+ 高度 | 视 widget 而定，必须是该 widget 的「视觉主角」 |
| **③ 细节 chip** | 1-3 个辅助信息（标签 / 计数 / 副标 / hash tag / mini stat），强化语义 | chip / pill / mini card 等 |
| **④ 底部操作 / 来源** | 「来自模块 X」/ 跳转提示 / 风险标注（注意：写操作回主窗） | 单行文本或图标行 |

**例外**：S 尺寸 widget 可省「细节 chip」，仅保留「顶部 ribbon + 中央主体 + 底部来源」三区（信息密度档 = 低）。

### 5.4 信息密度三档

| 密度档 | 含义 | 典型 widget |
|---|---|---|
| **低密度** | 一眼可懂，不需要操作；显示核心数字或图像 | 倒数日 / 年度进度条 / 情绪天气 / 白噪音 / Token 仪表 / 打字统计 |
| **中密度** | 一眼 + 操作；显示列表 / 详情卡片，可点击跳转 | 今日待办 / 三年前的今天 / 知识资产累计 / Memory 增长曲线 / 每日盲盒笔记 / 今日时间线 |
| **高密度** | 需要扫读 + 主动比较；多指标并列 + 多日趋势 | Hermes 状态 / 习惯热力图 / 时间流 |

**显式标注**：每个 widget 须在设计稿副标题中标注密度档（如「L 310×345 · 高密度」），交付研发时不得跳过。

### 5.5 三态主题 + 同源多皮肤

| 主题 | 适用场景 | 主色 | 玻璃参数 |
|---|---|---|---|
| Light | 默认 / 白天 | 白玻璃 `#FFFFFF` α0.72-0.75 | blur 20, white stroke 55%, shadow y8 α0.12 |
| Dark | 跟随系统 / 夜间 | 石墨 `#1C1C1E` α0.82 | blur 24, white stroke 18%, shadow y14 α0.24 |
| Tinted | 跟随壁纸染色 | 靛紫 → 紫罗兰渐变 `#5E5CE6`→`#A86BFA` | blur 20, white stroke 35%, indigo glow |

**混合策略**：在同一画板上允许**部分 widget 使用暗色玻璃**作为画风分水岭（如 Hermes 状态 / 今日时间线），但 widget 主体 + 对比 widget 必须经过验证不破坏视觉统一性。

**Tinted 边界**：渐变仅用于「Tinted 主题的 widget surface fill」，**不**用于 widget 内部的图形元素（图表 / 数字仍然用主题色板色）。

#### 5.6.3 圆角与阴影

#### 5.6.4 图标

## 9. 技术边界与工程约束

> 本节对齐 `architecture.md §23.11`（桌面投影工程实现）。

### 9.1 必须遵守的工程边界（与 PRD §7.12 DSK 强化）

| 约束 | 实现 |
|---|---|
| **独立 Swift extension target** | Xcode 工程须存在 `SophoNoteWidget` extension（WidgetKit）+ `SophoNoteControlModule` extension（macOS 26+ only） |
| **数据通道单向** | Rust 核心（Tauri 后端）→ App Group 共享容器（`group.com.sophonote.widgets`）→ Swift 端 **只读** 解析 |
| **Widget 不回写** | Swift 端不得直接调用 DocumentService；写操作必须通过 widgetURL 深链回主窗，由主窗负责执行 |
| **权限** | App Group 写权限在 macOS Sandbox 下受限：entitlements 须包含 `com.apple.security.application-groups` |
| **代码签名** | 首次提交评估：Apple Developer ID + 共享容器声明；notarization 通过后正式可用 |
| **Tahoe beta API 风险** | Control Center API 在 beta 期间不稳定，需准备 macOS 14-25 仅 widget 的降级方案（DSK-06） |

### 9.2 状态机与数据契约

#### 9.2.1 数据快照格式（Swift 端解析）

```json
{
  "snapshot": {
    "id": "uuid",
    "generated_at": "2026-08-20T18:50:00Z",
    "widgets": {
      "todo_today": { "rows": [...], "stats": {...} },
      "hermes_status": { "state": "...", "elapsed_m": 12, "queue": 2, "mem_writes": 3, "tokens": 8400 }
    }
  }
}
```

#### 9.2.2 刷新预算

- 系统预算：~40-70 次/天
- 触发刷新：**仅当数据变化时**（Rust 端 diff 检测 + Apple Push Notification 主动唤醒）
- 长间隔时间 widget（如年度进度条）每天仅刷新 1 次
- 高频 widget（Hermes 状态）使用 budget-aware refresh

### 9.3 性能与可访问性

- 加载时间：widget 启动 ≤ 200ms（cold start）
- 内存：≤ 30MB（macOS widget 上限）
- 可访问性：VoiceOver 完整朗读所有文本；Dynamic Type 支持字阶缩放
- 减少动效：在「减少动效」系统设置下 widget 不出现 sparkle / 时间流动
